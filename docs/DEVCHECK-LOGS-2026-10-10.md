## Подтверждённые проблемы и исправления

### 1. CPUINFO: отсутствующий профиль, P1

28 ошибок HookCore: по 14 для IoBridge.open и BlockGuardOs.open.
Первое сообщение — Logcat строка41588, 13:21:57.130; последнее — строка54283,
13:22:26.834. Стек ведёт через Lua script:19 в MockCpu.getContents().

Путь: XParam.createFakeCpuinfoFile/Descriptor → getSetting(soc.cpu.info.dump) →
при пустом значении XMockCall.getSelectedMockCpu → MockFileUtil.
Последняя утилита без проверки разыменовывала null.

Исправление: MockFileUtil возвращает null, если профиль или его содержимое
отсутствует/пустое. Lua уже умеет обрабатывать null без замены аргумента/результата.
Настроенный soc.cpu.info.dump по-прежнему имеет приоритет; выбранный legacy-профиль
по-прежнему используется. Проверены null и пустой профиль unit-тестами.

**Это исправляет исключение, но не создаёт отсутствующий профиль.** Без настроенного
содержимого CPUINFO остаётся оригинальным. Причину отсутствия конкретного сохранённого
профиля нельзя однозначно восстановить без снимка настроек; её не выдаём за
доказанный сбой кнопки «Свап» или базы.

### 2. Батарея: null Integer и неверная упаковка результата, P1

28 сообщений BatteryInterceptor (13:21:57.554–13:22:33.496). XParam.getSettingInt
намеренно возвращает null при отсутствующем/невалидном значении и выключенных
defaults. BatteryInterceptor присваивал это примитивному int и падал на unboxing.

Дополнительно по исходникам подтверждён дефект выражений `isLong ? long : int`:
Java продвигает обе ветки к long, поэтому даже getIntProperty получал Long.
Отдельного сообщения об этом дефекте в данном журнале нет.

Исправление: nullable-значения проверяются до арифметики; ненастроенные свойства
не заменяют оригинал. Расчёт charge/energy прекращается при недостающих входах.
Аналогичные места BatteryChanged Intent проверены и защищены; прежний явный
default количества циклов сохранён. BatteryValues.result отдельно возвращает
Integer либо Long. Три unit-теста: пропущенные параметры, единицы/границы,
точный runtime-класс результата и насыщение int.

### 3. Массовое сохранение многократно останавливает приложение, P1/P2

Всего 93 записи Force stopping flar2.devcheck: одна отдельная и пачки 49+43.
Не называем их падениями DevCheck. Каждый пакет настроек наследовал kill=true.

SettingExFragment теперь снимает снимок параметров в UI-потоке, записывает их
без промежуточных force-stop, активирует связанные хуки и один раз останавливает
целевое приложение при наличии успешных изменений и включённой опции kill.
Глобальный контекст не останавливается этим путём. Ошибка финальной остановки
логируется отдельно. UI отмечает сохранённым именно записанное значение,
не стирая более новый черновик, введённый во время записи.

Добавлена структурная регрессия порядка операций; это не заменяет измерение
числа force-stop на телефоне. Запись нескольких настроек всё ещё не является
единой транзакцией, и сбой посередине может оставить частично применённый набор.

### 4. Ложная ошибка пути базы, P2

SQLDatabase конструктор передавал каталог в ensureValidFile, который по контракту
отклоняет каталоги. Проверка перенесена на построенный путь файла базы.
Сам журнал сразу после ошибки показывает успешное открытие mock.db; доказательств
повреждения базы здесь нет. Никаких удалений, миграций или сброса БД не делалось.

### 5. Null provider result ошибочно объявляется сбоем, P2/P3

124 сообщения IntentQueryData про собственный PreferenceProvider DevCheck.
Возвращение null допустимо; текущая обработка и так возвращала false, не меняя
результат. Сохранено это поведение, убрана ошибочная запись Error с параметрами
чужого запроса. Ошибки непустых результатов и остальные проверки не отключены.

### 6. Пустые назначения и отсутствующий companion, P3

HookRepository больше не бросает искусственное исключение «No Hooks are Assigned»:
пустой набор — информационное сообщение и выход без установки.
XSecurity.getProFingerPrint отдельно обрабатывает NameNotFoundException для
необязательного eu.faircode.xlua.pro. Остальные ошибки остаются в диагностике.
Проверка caller и правила разрешений не изменены.

## Что не является доказанным сбоем XPL-EX

- Отказ первого способа Hidden API: в следующую миллисекунду второй способ успешен.
  Менять механизм по этому сообщению оснований нет.
- LSPosed «System feature passthrough»: намеренный пропуск legacy-хуков, не ошибка
  регистрации всех хуков. Политика сохранена.
- Системные Oplus/Athena/ANDR-PERF сообщения и записи других модулей, включая
  Oxygen Customizer: наличие рядом по времени не доказывает конфликт с XPL-EX.
- Method signature с `throws ClassNotFoundException` в строке First hook executed
  не означает выброшенное исключение.
- В текущем интервале 13:20–13:22 нет строк FATAL EXCEPTION/Fatal signal.
  Это не доказательство корректности всех хуков, отсутствия ANR или успешности
  всех подмен. Некоторые ошибки перехватчиков были пойманы и оставили оригинал.

В advanced_settings_content.xml удалены визуальные подписи трёх theme-кнопок.
Добавлены векторные auto (полутоновый круг), sun и crescent в едином наборе,
28dp, viewport24, контур2, центрирование без text/icon padding.

Высота52dp, равные веса, MaterialButtonToggleGroup, selectionRequired,

Прочие блоки интерфейса не редактировались. Геометрия проверена XML-тестом;
визуальная оценка на реальном экране и с TalkBack остаётся за проверкой на телефоне.
